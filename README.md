# Smart Crop Advisor

A location-based crop suggestion web app (SDG 2 — Zero Hunger). The browser finds the farmer's
coordinates, the backend fetches weather from Open-Meteo, and crops are suggested by one of two
**clearly different methods**:

| Mode | When | Method |
|------|------|--------|
| **Soil-informed** | Farmer has a soil test (N, P, K, pH) | Random Forest classifier trained on the Kaggle *Crop Recommendation Dataset* (7 features) |
| **Weather-only** | No soil report | Transparent **rule-based** ranking from `backend/data/crop_rules.json`. It is **not** a trained model, and soil values are never invented to feed the classifier |

No database, login, paid API or API key is needed. Recommendations are preliminary and must be
verified with local agricultural guidance.

## Dependencies

Backend (`backend/requirements.txt`): Flask, Flask-Cors, requests, python-dotenv, pandas, numpy,
scikit-learn, joblib, pytest.
Frontend (`frontend/package.json`): react, react-dom, vite, @vitejs/plugin-react.
You need **Python 3.10+** and **Node.js 18+** (with npm).

## Get the dataset (needed for the soil-informed mode)

1. Open https://www.kaggle.com/datasets/atharvaingle/crop-recommendation-dataset (free account).
2. Download and unzip it.
3. Put **`Crop_recommendation.csv`** in `smart-crop-advisor\backend\data\`.

The dataset is not bundled because its redistribution terms are set on Kaggle; check them
yourself. `train_model.py` prints the actual row count and crop labels it finds, so nothing is
assumed. Columns must be `N, P, K, temperature, humidity, ph, rainfall, label`.

## Run on Windows (Command Prompt)

### Backend — first Command Prompt

```bat
cd smart-crop-advisor\backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python train_model.py
python app.py
```

* `python train_model.py` needs the CSV from the previous section. It prints measured test
  accuracy, macro precision/recall/F1 and a classification report, then saves the model. If the
  CSV is missing it stops with a clear message. You may skip it and use only weather-only mode.
* The API now runs at **http://localhost:5000**. Open http://localhost:5000/api/health to check.
  Leave this window open.

### Frontend — second Command Prompt

```bat
cd smart-crop-advisor\frontend
npm install
copy .env.example .env
npm run dev
```

Open the URL Vite prints (normally **http://localhost:5173**).

* `frontend\.env` holds `VITE_API_URL=http://localhost:5000`. It must match the backend port
  (change both if you change `PORT` in `backend\.env`; also keep the frontend origin in the
  backend's `CORS_ORIGINS`). Restart `npm run dev` after editing `.env`.
* Browser location only works on **http://localhost** or **HTTPS**. Opening the app through a
  plain-HTTP network address (like `http://192.168.x.x:5173`) will make the browser refuse GPS;
  the manual location options still work.

## Using the app

1. Click **Detect My Location** and allow the browser prompt (or enter coordinates / search a
   place name manually). Weather loads once, and a **Retry** button appears if it fails.
2. Choose whether you have a soil test report.
   * **Yes** — enter N, P, K, pH (temperature, humidity and rainfall are pre-filled from your
     weather and editable) → ML recommendation.
   * **No** — get preliminary rule-based suggestions from weather only (optional season).
3. Read the method label, warnings and disclaimer. **Try again** lets you change inputs.

## API reference and how to test it (Command Prompt)

All errors look like `{"error": {"code": "...", "message": "...", "details": {...}}}`.
Status codes: `400` malformed request, `422` missing/invalid values, `502/504` weather service
problem, `503` model unavailable, `500` unexpected.

**Health** (reports real state):

```bat
curl http://localhost:5000/api/health
```

**Weather** (needs internet; Chennai as an example — use any coordinates):

```bat
curl "http://localhost:5000/api/weather?latitude=13.08&longitude=80.27"
```
Returns current conditions, a 7-day forecast and a ~12-month historical average, each labelled.
Invalid coordinates return `400`; upstream failures return `502`/`504`.

**Soil-informed prediction** (needs the trained model, otherwise `503`):

```bat
curl -X POST http://localhost:5000/api/recommend -H "Content-Type: application/json" -d "{\"mode\":\"soil\",\"N\":90,\"P\":42,\"K\":43,\"temperature\":25.5,\"humidity\":80,\"ph\":6.5,\"rainfall\":200}"
```

**Weather-only recommendation** (works without the model or soil data):

```bat
curl -X POST http://localhost:5000/api/recommend/weather -H "Content-Type: application/json" -d "{\"temperature\":27,\"humidity\":80,\"rainfall\":200,\"season\":\"kharif\"}"
```
`rainfall` is an **average monthly** figure in mm. `humidity`, `rainfall` and `season` are
optional; missing ones are reported in `missing_data_warnings`.

**Place search** used by the manual location option:
`curl "http://localhost:5000/api/geocode?name=Hosur&region=tamil%20nadu"`

## Tests

```bat
cd smart-crop-advisor\backend
venv\Scripts\activate
python -m pytest -v
```

| Group | Needs |
|-------|-------|
| Everything except the last test | Nothing: no internet, dataset or trained model. Weather calls are mocked. |
| Prediction / API tests with a model | A **small synthetic fixture model** built inside the tests from random numbers. It only proves the code path works. It is not real data. |
| `test_real_model_prediction` (marker `real_model`) | The **downloaded dataset and a model trained with `train_model.py`**; it is skipped automatically otherwise. |

Covered: health (with/without model and dataset), invalid coordinates, weather API errors
(timeout, unreachable, HTTP error, bad JSON), missing model, missing/invalid dataset, invalid
N/P/K, pH, humidity, missing features, invalid bodies, soil prediction, weather-only
recommendation, geocoding.

## Implemented features

* Browser geolocation on click only; denied/unavailable states handled; manual coordinates and
  place search (village, district, state) fallback; nothing stored
* Backend weather service: current, 7-day forecast, ~12-month historical average, timeouts,
  small in-memory cache, no polling, retry button
* Two distinct, labelled recommendation modes with input validation and consistent JSON errors
* Training script with data validation, reproducible split (seed 42), measured metrics, saved
  feature order and per-crop training ranges
* Out-of-training-range warnings; model scores explained as *not* real-world probabilities
* Responsive, accessible React dashboard; About section
* Automated tests with mocked external services

## Limitations and manual steps

* The dataset CSV must be downloaded manually; the model is trained on your machine.
* The Kaggle dataset's N/P/K use its own scale, and its `rainfall` period is unspecified. The app
  feeds it average monthly rainfall. High accuracy on this dataset's test split does not mean the
  model is accurate on real farms.
* `crop_rules.json` holds **illustrative** crop requirement ranges, not locally validated
  agronomy. Edit it to match your local guidance. Season names use the Indian kharif/rabi/zaid
  convention.
* Weather-only mode ignores soil, irrigation, variety, elevation and markets.
* Open-Meteo's free service has usage limits and terms (https://open-meteo.com/en/terms).
* No deployment configuration is included; this is a local development setup. The Flask
  development server is not for production use.

## How the pieces communicate

```
Browser (React)  ──fetch──▶  Flask API (localhost:5000)  ──requests──▶  Open-Meteo
   │ Geolocation API            │  weather_service.py
   │                            ├─ predict.py ──▶ models/crop_model.joblib (Random Forest)
   │                            └─ crop_rules.py ──▶ data/crop_rules.json
   ◀──────── JSON (results or {"error": ...}) ────────┘
```

1. The browser obtains coordinates (Geolocation API or manual entry).
2. React calls `GET /api/weather`; Flask validates, calls Open-Meteo and returns normalised JSON.
3. The user's choice decides the endpoint: `POST /api/recommend` (soil → trained model) or
   `POST /api/recommend/weather` (rules). Flask validates every field, runs the matching method
   and returns the result with a disclaimer, or a structured error that the UI shows as a failure.
